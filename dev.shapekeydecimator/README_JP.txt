# Shape Key Decimator

シェイプキーが動かすポリゴンを削除するのではなく、**削減（デシメーション）**するための、非破壊型 Unity コンポーネントです。Prefabulous Universal の **Delete Polygons** コンポーネントに着想を得ています。

## 必要環境

Modular Avatar
https://modular-avatar.nadena.dev/

## インストール

以下のようにファイルを配置してください。`Editor` フォルダー名は変更しないでください。

```text
Assets/ShapeKeyDecimator/
    DecimatePolygonsByShapeKey.cs
    Editor/
        ShapeKeyDecimatorUtil.cs
        ShapeKeyMeshDecimator.cs
        ShapeKeyDecimationProcessor.cs
        ShapeKeyDecimatorPreviewManager.cs
        ShapeKeyDecimatorLocalization.cs
        ShapeKeyDecimatorNdmfPlugin.cs     <- MA を使用しない場合は削除してください
        DecimatePolygonsByShapeKeyEditor.cs
```

## 使用方法

アバター内の任意の GameObject（通常はルートがおすすめ）に **Shape Key Decimator → Decimate Polygons By Shape Key** を追加します。

1. 削減したいメッシュを **スキンドメッシュ** にドラッグします。対象は常に明示的に指定され、このコンポーネントが階層を検索することはありません。指定したメッシュだけが処理されます。
2. **削減するシェイプキーを追加** を開き、シェイプキーの **+** を押します。シェイプキーが有効になり、**削減率**スライダー付きの行が追加されます。
3. スライダーを調整します。`0` = 削減なし、`1` = トポロジーが許す限り最大まで削減します。
4. 必要に応じて **メッシュ全体** のスライダーも調整すると、それ以外の部分もまとめて削減できます。

表には各行ごとに、その処理対象となる三角形数と、削減後に残る三角形数が表示されます。**合計ポリゴン数**には、選択したすべてのメッシュの変更前 → 変更後が表示されます。

Play モードに入るかアバターをアップロードするまでは、メッシュは変更されません。その時点で MA が一時コピーに対して処理を実行するため、元のメッシュアセットは一切変更されません。

## ヒント

**詳細設定** の **法線の最大許容角度** を調整してください。モデルによっては非常に小さい値が最適な場合もあれば、100 前後が適している場合もあります。

シェイプキーによる削減後に境界部分が不自然に鋭くなる場合は、**領域の境界を保護** をオフにすると改善することがあります。

スキンドメッシュごと（またはグループごと）に別々の GameObject を作成し、それぞれへ **Decimate Polygons By Shape Key** コンポーネントを追加することをおすすめします。

## 推定値と実測値

表には 2 種類の表示モードがあり、現在どちらが表示されているかがヘッダーに示されます。

**推定値**（`~` が付き、ヘッダーは「推定」）

領域内の三角形数 × スライダー値から瞬時に計算されます。**すべてのエッジ収縮が成功する**と仮定しているため、削減量の上限を示す値であり、実際の結果を予測するものではありません。どれだけの収縮が条件によって却下されるかは、実際にアルゴリズムを実行するまで分からないためです。

**実測値**（`~` が付かず、ヘッダーは「実測」）

現在の設定で実際に削減処理を行った正確な結果です。**正確な結果を実測する** を押すか、**プレビュー** を有効にすると取得できます。プレビューは実際の削減処理を行うため、その結果がそのまま表示されます。測定結果は出力に影響するすべての設定を元にキャッシュされるため、設定を変更すると無効になり、自動的に推定値へ戻ります。

これは特に **法線の最大許容角度** に大きく影響します。

これはエッジ収縮を却下する判定値です。`0` の場合は三角形が一切回転できないため、曲面メッシュではほぼすべての収縮が却下され、実際には何も削減されません。それでも推定値は最大削減されたかのように表示されます。

値を大きくすると削減量は増え、小さくするとより保守的になります。15° 未満ではインスペクターに警告が表示されます。

同様の影響は、UV シーム保護、境界保護、サブメッシュ保護、および有効な収縮候補がなくなる場合にも発生します。

## メッシュ全体とシェイプキーを同時に使う場合

両方とも同時に動作しますが、処理順は固定です。

**最初にすべてのシェイプキー領域が処理され、その後にメッシュ全体の削減が残りに対して適用されます。**

つまり、

* シェイプキーのスライダー = 「この部分を他より強く削減する」
* メッシュ全体 = 「その後、全体をさらに削減する」

という意味になります。

このため、**メッシュ全体** の行に表示される三角形数は元のメッシュ全体ではありません。シェイプキーによる削減後に残った三角形数になります。

削減量は加算ではなく乗算的に重なります。例えばシェイプキーを 0.5、メッシュ全体も 0.5 にした場合、重なった領域は約 25% が残り、0 になるわけではありません。

**領域の境界を保護** はメッシュ全体では意味を持ちません(領域外が存在しないため)ですが、開いた境界、サブメッシュ境界、法線の最大許容角度による保護は引き続き適用されます。そのため、服の端が裂けたり、頂点がマテリアル境界を越えて移動したりすることはありません。

## 常に削減しない(ブラックリスト)

顎の骨と正確に一致させたい顎のシェイプキーなど、絶対に形状を変えたくないシェイプキーもあります。**ブラックリストに追加** を展開して **+** を押すと保護できます。ブラックリストに登録したシェイプキーは通常のシェイプキーリストには同時に追加できません(片方に追加すればもう片方から自動的に削除されます)。メッシュ全体の削減もその頂点を除外するため、どちらの経路からもその領域が削減されることはありません。

## オプション

| オプション           | 説明                                                                            |
| --------------- | ----------------------------------------------------------------------------- |
| **スキンドメッシュ**    | 削減対象のレンダラーです。このリストが空の場合は何も処理されません。                                            |
| **メッシュ全体**      | すべてのシェイプキー領域の処理後にメッシュ全体へ適用される削減率です。                                           |
| **変位のしきい値**     | ブレンドシェイプによる頂点移動量がこの値を超えた頂点を領域に含めます。エクスポーターが極小のデルタを大量に出力している場合は値を上げてください。      |
| **領域の境界を保護**    | 領域の縁の頂点を固定し、削減されない部分との境界を維持します。より高い削減率が必要ならオフにしてください。                         |
| **開いた境界を保持**    | メッシュの開いた端（袖口、裾、まぶたなど）の頂点を保護します。ただし境界に沿った収縮は許可されます。                            |
| **サブメッシュ境界を保持** | マテリアル境界をまたぐ収縮を防ぎます。                                                           |
| **UVシームを保持**    | UV シーム上の頂点がシームの内側へ移動しないよう固定します。通常はオンのままにしてください。                               |
| **UV誤差の重み**     | テクスチャの歪みをどれだけ重視するかを指定します。`0` は UV を無視、`1` は形状誤差と同程度、それ以上ではシルエットよりテクスチャを優先します。 |
| **法線の最大許容角度**   | 周囲の三角形がこの角度以上回転する収縮を却下します。小さいほど保守的、大きいほど多く削減されます。非常に小さい値ではほとんどの収縮が却下されます。     |

## プレビュー

**削減をプレビュー** を押すと、一時的に削減後の結果へ差し替えられ、シーン上で確認できます。有効中はボタンが緑色になり、`PREVIEW ON` と表示されます。

有効にすると各対象レンダラーの隣へ削減済みコピーが生成され、元のレンダラーは無効になります。

無効にすると元へ戻り、コピーと生成されたメッシュは削除されます。

プレビュー中にスライダーや設定を変更すると、自動的に再生成されます。

再生成はスライダーを離して少し待ってから行われます。削減処理は比較的重いため、ドラッグ中に毎フレーム再生成されることはなく、最後に一度だけ実行されます。

再生成待ちの間はボタンに `updating…` と表示されます。

プレビューは一時的な機能であり、次のような場合でも自動的に後始末されます。

* Play モードへ入る前に自動で終了します。
* スクリプトの再コンパイル前に削除されます。
* Preview オブジェクトには `DontSave` が設定されるため、シーンやビルドへ保存されることはありません。
* プレビューによって無効化されたレンダラーは記録され、クラッシュなどで正常終了できなかった場合でも次回ロード時に復元されます。
* プレビュー中にコンポーネントを削除した場合に残ったオブジェクトは次回ロード時に自動削除されます。必要なら **Tools → Shape Key Decimator → Turn Off All Previews** でいつでも強制削除できます。

## ヒエラルキーに削減済みコピーを作成

画面下部のボタンを押すと、その場で結果を確定します。

* 削減後のメッシュを `Assets/ShapeKeyDecimator Output/` に保存
* レンダラーの GameObject を隣へ複製し、名前を `... (Decimated)` に変更
* 複製側を新しいメッシュへ差し替え、ブレンドシェイプ値を復元し、このコンポーネントを削除

## 注意事項・制限

* **ポリゴン数** 列は、領域内に**完全に含まれる**三角形のみを数えます。削除対象になるのはそれらだけです。
* デシメーションされるのは三角形トポロジーのサブメッシュのみです。それ以外のトポロジーはインデックスを付け替えて保持されます。
* 領域ごとの三角形数はメッシュ単位でキャッシュされます。モデルを再インポートして数値がおかしい場合は **Tools → Shape Key Decimator → Clear Cached Triangle Counts** を実行してください。
